## 6. EAS Build — when you're ready to make a binary

```bash
# 1. Install the EAS CLI
npm install -g eas-cli

# 2. Sign in (creates an Expo account if needed)
eas login

# 3. From the frontend folder
cd /app/frontend
eas init           # creates a project ID and writes it into app.json
eas build:configure # links iOS / Android credentials

# 4. Build for iOS (creates an .ipa you can upload to TestFlight)
eas build --platform ios --profile production

# 5. Build for Android (creates an .aab you upload to Play Console)
eas build --platform android --profile production

# 6. (Optional) auto-submit
eas submit --platform ios
eas submit --platform android
```

When `eas init` runs you'll get a **Project ID** — paste it into `app.json`
under `extra.eas.projectId`. Same for the `owner` field (your Expo username).

## 8. Common rejection reasons to avoid

- ❌ **No privacy policy URL** — fix: host the privacy.tsx contents publicly
- ❌ **Subscriptions not using Apple's IAP** — Apple requires in-app subscriptions be sold via StoreKit, NOT Stripe, when sold inside the iOS app. Workaround: keep Stripe checkout for web/Android, build a separate StoreKit flow for iOS, OR exempt the app from this rule by selling subscriptions only via the website (App Store calls this a "reader app"). **You MUST decide this before iOS submission.** If you want, I can build the StoreKit flow next.
- ❌ **Mentioning prices that include "/month" without saying "auto-renewable"** — fix is in the existing paywall copy
- ❌ **AI content without medical disclaimer** — already covered in `terms.tsx` clause 5
- ❌ **Login required to view the app demo** — Apple wants reviewers to see the app. We have the `amazon-review@fitlux.com` account; reuse it: paste credentials into the App Review Information section.
